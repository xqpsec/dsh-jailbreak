卡住了把 doctor 四行贴上来，讨论区 或 群 都行。

端点怎么填：五个后缀对四种协议

「装了没反应」的第二类原因是挂上了，但请求没命中；第三类是命中了，但字段读错了。两类都在端点层，靠两行 doctor 输出就能分清。

先看现象。审计里出现这样的两条，就是命中但没改写：
{"debug":"matched","protocol":"responses"} 后面跟着 changed:false
Responses 的 body 里没有 messages，它用 input；Gemini 也没有 messages，它用 contents。按 messages 找工作的人，在这两种协议上永远找不到。

一、五个后缀、四种协议

后缀协议典型来源
/chat/completionsopenaiDeepSeek 官方、各类 OpenAI 兼容中转、vLLM、Ollama、one-api、new-api
/messagesanthropicAnthropic Messages；DeepSeek 账号通道也走这条（api.deepseek.com/anthropic/v1/messages）
/responsesresponsesOpenAI Responses API 形状的 provider
/completionsopenai只暴露裸补全的老中转，不带 chat 前缀
:generateContentgeminiGemini 原生 REST（models/<model>:generateContent）

判定按后缀长度降序：/completions 是 /chat/completions 的后缀，先判短的会把后者误判成裸补全。认不出的自定义后缀一律落到 openai，不报错——所以拼错后缀的表现不是报错，是「命中但没改」。

二、四种协议各改哪个字段

协议输入系统字段写回位置
openaimessages[]messages[0].role==="system"messages 里的 system 段
anthropicmessages[]顶层 systembody.system
responsesinput（字符串或 [{role,content}]）顶层 instructionsbody.instructions
geminicontents[{role,parts[]}]systemInstructionbody.systemInstruction={parts:[{text}]}

两个实现细节：Responses 的 input[].content 可能是 input_text / output_text 块，要按块取 text；Gemini 的 systemInstruction 必须是 {parts:[{text}]} 对象，塞纯字符串上游会 400。

三、三条自查

node bin/aecot.js doctor --profile web
  • endpoints：生效的后缀列表里，有没有你真实在用的那条；
  • transport-hits：最近若干条判定里 matched / not-matched 的比例；
  • system-probe（审计 JSON 里）：注入完成后 system 段的前 700 字符，能证明字节真的进了 body。
tail -n 40 gate-audit.jsonl | jq -c 'select(.debug=="system-probe") | {protocol, chars}'

chars 为 0 或这行不出现 → 协议层没跑到，回到第二节查字段；chars 正常但模型行为照旧 → 上游把 system 丢了，拿同一条 system 直连官方端点对比。

四、四个高频错写

写法结果正确写法
/v1/chat/completions/ 尾部多斜杠不命中（严格 endsWith）去掉尾部斜杠
/v1/chat落 openai，按 messages 找输入找不到写全 /chat/completions
Gemini 的冒号写成斜杠不命中保留 :
中转同时开两种路径只配了一个一半请求不命中两个都写进 suffixes

五、把端点收窄

默认 hosts: ["*"] 全放行、五个后缀全开，多数人不用动。要动有三个位置，优先级从高到低：数据根目录 live.json → 插件目录 live.json → 环境变量 DSH_JAILBREAK_ENDPOINTS。

{
  "hosts": ["api.deepseek.com", "*.example.com"],
  "suffixes": ["/chat/completions", "/messages"],
  "skipHosts": ["localhost"]
}

*.foo.com 同时匹配 foo.com 自身；skipHosts 优先于 hosts；enabled:false 整层关掉，doctor 会打印「端点注入已关闭」；配置写坏就回默认全放行，不影响装完即用。
