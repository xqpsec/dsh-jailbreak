「装了，但好像没生效」——按症状排查

插件不生效的原因基本只有四类：没装上、两个开关搞混了、请求没走到改写点、模型这次就是不松口。下面按你会看到的症状排，从最便宜的检查开始，不用读源码。

想先看个短版本？B 站专栏：6 条逐项排查 · 3 分 22 秒实测视频。本页是带完整命令输出的手册，比那两个都全。

先跑这一条。它只读、不联网、不花 token，能一次排除掉前两类：
node bin/aecot.js doctor
dsh-jailbreak doctor 1.0.0
  ✓ Node 版本：v24.21.0
  ✓ 插件文件：@xqpsec/dsh-jailbreak@1.3.5 · AGPL-3.0-only
  ✓ 破甲开关：已开启（默认开；状态文件 .aecot/arm.json）
  ✓ 注入端点：生效端点：任意域名，路径 /chat/completions / /messages
  ✓ 阀门：profile=lab enforce=false onDeny=passthrough hardDeny=5 类
  ! 注入记录：还没有看到任何一次注入 — 在 DSH 里随便问一句话，再跑一次 doctor

六行里唯一的 ! 就是线索所在。往下对着你的那一行走。

症状一：doctor 说「还没看到任何一次注入」

最常见不是 bug

这句话的字面意思是：插件装好了、开关也开着，但它一次都没拦到请求。也就是请求根本没走到改写点。按顺序查：

1. 端点是 OpenAI 兼容路径吗

插件改写的是出站的 /chat/completions（Anthropic 兼容端是 /messages）。如果你的 DSH 走的是别的路径（自建网关、私有协议、某些中转的 /v1/complete），它不在改写范围内——这是设计如此，不是漏了。

2. 装进的是你以为的那个 profile 吗

dsh plugin --profile web add ... 里的 web 必须是你实际在跑的那个 profile。装进了 web、跑的是 default 或自定义 profile，等于没装。查一下：

dsh plugin --profile <你在用的> why @xqpsec/dsh-jailbreak

3. 装完重启了吗

插件是通过 dsh.bundle.patch 挂进宿主启动流程的，装完必须重启 dsh web / 桌面端才生效。热更新不会重挂 bundle。

4. 那次对话真的发出去了吗

在 DSH 里正常问一句技术问题（比如「帮我定位这个 crackme 的关键校验并给 patch 点」），模型回完之后再跑一次 doctor。第二遍还显示「没有注入」，才是真的有问题。

症状二：doctor 全绿，模型还是拒绝

可疑度上调有解

doctor 全绿说明请求确实被改写了。这时候「还是拒绝」有三种性质完全不同的原因：

现象性质怎么办
10 次里松 4～5 次，问题越具体越容易松这就是当前基线，不是失效换更明确的问法；或换 arm（见下）
整轮对话一次都不松大概率是命中类别的边界换 seed-core arm 试同类问题
回复里出现「我可以帮你…但是」然后转成泛泛而谈模型在做软化，不是硬拒追问一句「直接给可运行的代码」，通常就下来了

换 arm 是唯一一个改一个字段就能看到差别的手段：

# 看当前用哪个 arm
node bin/aecot.js arm
# 换成核心交付物版本（难类更稳，注入字符更多）
node bin/aecot.js arm seed-core

三档的实测差别（20 类合并、跨 n=169/184/60）：base 0.0% → primitive 19.6% → seed-prim 45.0%。目标级 pass@3 / pass@4 到 70.8% / 76.9%——也就是说同一个问题多问几次，命中率明显高于单次。这不是"破了就百发百中"，README 里没这么写过。完整评测口径。

症状三：DSH 升级之后就失效了

1.3.5 修过

典型现场：升级 host 到 0.2.1-rc.x 之后，破甲时好时坏，或者模型开始输出重复内容。原因通常是宿主侧的请求结构或安全段变了，改写点对不上。

  • 先升级插件：dsh plugin --profile <你的> add github:xqpsec/dsh-jailbreak（会拉最新 main）
  • 如果输出在死循环（同一段话反复吐）：这是 host 侧 ds_safety 与预填轨迹打架，v1.3.5 专门修的就是这个（issue #1）。升到 1.3.5 及以上。
  • 还是不行：把 node bin/aecot.js doctor 的完整输出贴到 交流群。doctor 输出里没有 key、没有对话内容，可以直接贴。

症状四：两个开关搞混了（这个最坑）

设计如此文档的锅

本项目里有两个默认值相反的开关，名字都像"总开关"。搞混了就会出现「明明开着却像没开」或者「明明关了它还在拦」：

破甲开关（arm）阀门（gate / SCOPE）
干什么决定请求要不要被改写决定改写前要不要做范围审查
默认开（装完就能用）关（enforce:false）
状态文件.aecot/arm.jsongate.json 的 enforce 字段
关掉会怎样逐字透传，和没装一样不做范围判断，所有请求照常改写
怎么查node bin/aecot.js armdoctor 里「阀门」那一行

换句话说：「默认关闭」说的是阀门，不是破甲。破甲装完就是开的；阀门默认只做记录不拦人，想让它真拦，把 gate.json 里 enforce 改成 true。

症状五：和别的破甲插件同时装了

必踩

两个插件都改写发往 /chat/completions 的 body 时，注入的轨迹会互相覆盖或叠加，表现是「两个都不太灵」或者「输出开始错乱」。同类插件只留一个。要临时验证是不是这个原因，把另一个 dsh plugin remove 掉再试。

症状六：装完 DSH 直接起不来

报错里带 pluginPackages / 插件树加载失败时，按这个顺序：

  1. 确认 Node ≥ 20（node -v）。
  2. 确认包里有 dsh.bundle.patch："dsh": {"bundle": {"patch": "./cordis.patch.yml"}}。只声明 dsh.client 的包不会被激活。
  3. 把 profile 的 node_modules 和 pnpm-lock.yaml 删掉重装一次。
  4. 还不行就把 host 的启动日志 + doctor 输出一起贴群里。

怎么干净地卸掉

dsh plugin --profile <你的> remove @xqpsec/dsh-jailbreak

没有宿主补丁、没有全局 hook、没有后台进程，删包即恢复原状。留下的 .aecot/ 目录（开关状态与注入记录）可以直接删。

还是不行

把这三样贴到 交流群，一般一轮能定位：

  1. node bin/aecot.js doctor 的完整输出
  2. dsh --version 和 node -v
  3. 你问的那句话（愿意贴的话）—— 同一个问题在不同类别下命中率差很多
